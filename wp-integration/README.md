# Агростандарт — компоненты для WordPress

Готовый набор блок-паттернов Gutenberg, собранный из живого сайта
(`agrostandart_site_redesign.html`) и дизайн-системы. Разметка и стили
1:1 совпадают с сайтом, но упакованы так, чтобы ставиться в любой
WordPress без конфликтов с активной темой.

## Что внутри

```
agrostandart-patterns/
  agrostandart-patterns.php          — плагин: подключает шрифты и стили, регистрирует паттерны
  assets/
    agrostandart-design-system.css   — вся дизайн-система, целиком в .as-agrostandart
  patterns/
    00-header.html  … 10-footer.html — 11 независимых секций сайта
```

Каждая секция — самостоятельный блок `core/html` («Пользовательский
HTML» в редакторе): свою разметку, стили и JS можно вставлять в любом
порядке и на любой странице, не боясь, что что-то сломается без
остальных секций.

## Почему это безопасно ставить поверх любой темы

- Все CSS-правила и переменные живут только внутри `.as-agrostandart`
  — ни `:root`, ни `body`, ни глобальные `h1/h2/h3` не переопределяются.
  Классы вроде `.card`, `.btn`, `.grid` не «протекают» за пределы блока.
- Все id (`#as-nav`, `#as-send`, `#as-year`…) — с префиксом `as-`,
  чтобы не столкнуться с id темы или других плагинов.
- Каждый паттерн подключает свой JS в `<script>` внутри собственного
  блока и ищет элементы только через `document.currentScript.closest('.as-agrostandart')`
  — паттерны не мешают друг другу и не падают, если какого-то из них
  нет на странице.

## Установка

1. Скопируйте папку `agrostandart-patterns/` в `wp-content/plugins/`
   (обычный плагин) **или** в `wp-content/mu-plugins/` (must-use —
   включится сам, без активации).
2. Если ставили как обычный плагин — зайдите в **Плагины** и
   активируйте «Агростандарт — блок-паттерны».
3. Откройте редактор любой страницы → кнопка **добавить блок** (+) →
   вкладка **Паттерны** → категория **Агростандарт**. Все 11 секций
   будут там, вставляйте по порядку (шапка → герой → … → футер) или
   выборочно.

Обновление сайта = обновление файлов внутри `patterns/*.html` и
`assets/agrostandart-design-system.css` — плагин ничего не хранит
в базе, конфликтов при обновлении версии не будет.

## Что стоит донастроить на стороне WordPress

- **Изображение мешка** в `01-hero.html` сейчас — то же самое
  изображение, что было в исходном HTML (встроено как base64, чтобы
  паттерн работал «из коробки»). Для продакшена лучше загрузить его
  в Медиатеку и заменить `<img class="bag" src="data:...">` на обычный
  URL — так браузер сможет кэшировать файл отдельно от HTML страницы.
- **Ссылки-заглушки**: телефон `+375 (__) ___-__-__` и УНП в шапке/
  контактах/футере — их нужно заполнить реальными данными перед
  публикацией.
- **Форма заявки** (`09-contacts.html`) сейчас отправляет данные через
  `mailto:` — открывает почтовый клиент пользователя. Если на сайте
  уже есть форма-плагин (Contact Form 7, WPForms и т.п.), поля `input/
  select/textarea` внутри `.form-grid` можно заменить на шорткод формы,
  сохранив обёртку и классы для того же внешнего вида.
- **Скролл-анимация появления** (`.reveal`) использует
  `IntersectionObserver` — работает во всех современных браузерах без
  дополнительных библиотек.

## Мобильная адаптивность

Брейкпоинты сохранены из production-версии сайта и проверены на
ширинах 390–1920px:

| Ширина      | Что меняется |
|-------------|--------------|
| ≤ 1040px    | герой и блок «качество» в один столбец, сетки 4→2, мешок и карточка продукта — в ряд |
| ≤ 860px     | навигация уходит в бургер-меню |
| ≤ 680px     | все сетки в один столбец, отступы секций уменьшены, декоративные полосы скрыты |

## MCP WordPress

На момент подготовки этого пакета в сессии не был подключён MCP-сервер
для WordPress, поэтому публикация не выполнялась — набор подготовлен
как самодостаточные файлы. Как только сервер будет подключён, эти же
файлы можно передать через него (например, залить `agrostandart-
patterns/` как плагин через WP REST/MCP-инструмент и активировать) без
каких-либо изменений в структуре.
